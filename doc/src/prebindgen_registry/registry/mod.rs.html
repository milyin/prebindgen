1//! Which type conversions a binding needs, and whether it has them all.
2//!
3//! # The boundary
4//!
5//! [`Flat`](prebindgen_flat::flat::Flat) describes the source Rust code. A binding
6//! puts a wrapper on each side of an FFI boundary — generated Rust that the
7//! destination language can call, and destination-language code shaped to match
8//! it (`#[repr(C)]` structs and a C header; JNI externs and Kotlin classes).
9//!
10//! ```text
11//!    source flat API              generated wrapper            destination
12//!    (idiomatic Rust)                                            language
13//!    ────────────────             ─────────────────            ────────────
14//!    fn ledger_filed(&Ledger) ──► #[no_mangle] extern fn  ◄──►  external fun
15//!         -> Option<Report>         (jlong) -> jlong             fun filed(): Report?
16//!                                       ▲
17//!                                       └── the boundary: the WIRE
18//!                                           jlong / jint / jobject  (JNI)
19//!                                           *const T / size_t       (C)
20//! ```
21//!
22//! The wrapper's **body** speaks source Rust; its **signature** speaks wire. The
23//! translation between the two is a *conversion*, and collecting them is this
24//! module's whole job.
25//!
26//! # What a conversion is
27//!
28//! The adapter's business. It keeps the conversion itself; what it hands back
29//! is an [`Answer`], naming the crossings this one delegates to. That is what
30//! reachability walks, and it is all the registry needs to know.
31//!
32//! A composite need not cross whole. `Option<T>` may cross as a `T` carrying a
33//! niche value, as a `(bool, T)` pair, or as leaves delivered separately — which,
34//! is the adapter's choice, and the registry records it so the emitter can call
35//! it by name and the destination side can be written to match.
36//!
37//! Conversions are **directional**, which is why [`Direction`] is half of a
38//! [`Crossing`] rather than a name prefix on two tables. `&str` inbound is a
39//! `jstring` to decode, outbound a `jstring` to allocate, and one direction may
40//! be convertible while the other is not. A callback flips it — `impl
41//! Fn(Sample)` is an *input* whose argument crosses *outbound*.
42//!
43//! # What the registry does
44//!
45//! It **derives** the set, then **checks it is complete**.
46//!
47//! A binding names a surface: these functions, these types, these consts. Far
48//! more types than that must convert — parameter and return types, type
49//! arguments, struct fields, enum payloads, callback arguments in the flipped
50//! direction, and the leaves a decomposed value arrives in. Computing that
51//! closure is the work; completeness is meaningful precisely because the set is
52//! derived here rather than handed over.
53//!
54//! **It never writes a conversion.** It cannot — only a language adapter knows
55//! what a `jlong` handle or a `*const T` is. The registry decides *which* are
56//! needed, asks the adapter for each, and fails naming any that could not be
57//! supplied.
58//!
59//! # In, and out
60//!
61//! | in | |
62//! |---|---|
63//! | the model | [`Flat`](prebindgen_flat::flat::Flat) — what the source offers |
64//! | the crossings | which `(direction, type)` pairs actually cross |
65//! | the decompositions | how a composite crosses in pieces: which leaf crossings that adds, and which whole-value crossing it removes |
66//! | a conversion builder | the [`Prebindgen`] adapter |
67//!
68//! Out: a conversion for every type in the closure — or a failure naming the
69//! ones that must convert and cannot. The emitter then writes the file: the
70//! conversions, and the per-item wrappers that call them.
71//!
72//! # Using a registry
73//!
74//! **Describe it, hand over the answers, read it.** Two types, because those
75//! are two different things: a [`RegistryBuilder`] is still being described,
76//! and a [`Registry`] is finished and answerable.
77//!
78//! ```text
79//!   describe    builder(flat) · export · cross · decompose · depends
80//!      ↓
81//!   the demand  crossings()      → every crossing needing a conversion,
82//!      ↓                           sorted so each type's inners come first
83//!   the answers convert_with(f)  → one call per crossing, in that order
84//!      ↓        conversions(map) → or hand over a map you built yourself
85//!      ↓
86//!   close       build()          → fails naming any reachable crossing with
87//!      ↓                           no conversion
88//!   read        flat · exports · conversion(dir, ty) · decomposition(site) · …
89//! ```
90//!
91//! Most types need no declaring: they are reached by walking a declared
92//! element's signature, and deriving them per **usage** is what keeps an
93//! output-only type from being demanded as an input too. Measured: dropping the
94//! declaration-as-root for every type with a captured body leaves the generated
95//! output byte-identical.
96//!
97//! But a type with **no captured item behind it** — `ptr_class!(zenoh::KeyExpr<'static>)`
98//! on a re-exported foreign type — appears in no signature this model can walk,
99//! so nothing derives it and the declaration is the only statement that it
100//! crosses at all. That is what `cross` is for, and why the input cannot be
101//! elements alone.
102//!
103//! ```ignore
104//! let mut builder = Registry::builder(flat)?;
105//! for name in &self.exported    { builder = builder.export(name); }
106//! for ty in &self.foreign_types { builder = builder.cross(Direction::Deconstruct, ty); }
107//!
108//! let registry = builder
109//!     .decompose(self.decompositions())
110//!     // `built` already holds everything this crossing composes from: that is
111//!     // what sorted means.
112//!     .convert_with(|crossing, built| self.convert(crossing, built))?
113//!     .build()?;
114//!
115//! self.emit(&registry, out)   // read-only from here
116//! ```
117//!
118//! Prefer to drive the walk yourself? `crossings()` hands over the same list in
119//! the same order, and `conversions(map)` takes the result — the two compose,
120//! and neither is a second mechanism.
121//!
122//! **Nothing here calls back into the generator** — not by trait hook, and not
123//! by a `next_request`/`supply` pull loop either, which is the same protocol
124//! with the arrow flipped. `convert_with` is not that: the walk finishes before
125//! it returns, the closure is the caller's, and the builder chooses nothing
126//! about when it runs. It is `crossings()` plus a `for` loop, written once.
127//!
128//! What makes a single hand-off possible is the **sort**. The demand's edges
129//! (`immediate_edges` — generic arguments, tuple/reference/slice targets,
130//! declared struct fields, and `impl Fn` arguments with the direction flipped)
131//! are structural, so they are known without asking anyone. Ordering
132//! the closure by them means a generator building `Option<Handle>` already holds
133//! `Handle`, which is why it can work from a flat list instead of being called
134//! back per type. It also means each crossing is offered exactly once: a
135//! generator's `None` says *cannot*, never *not yet*.
136//!
137//! A `None` is not itself a failure. The scan over-approximates deliberately —
138//! every nested position, every declared struct in both directions — so whether
139//! a gap matters is reachability from the exports, which `build` decides.
140//!
141//! The structure covers almost every dependency, because an `Option<T>`
142//! visibly contains a `T`. What it cannot show is one a *declaration* creates —
143//! a `convert!` chaining through a helper's parameter type, or a callback
144//! argument delivered as plan leaves. Those are stated with `depends`, and
145//! getting one wrong is not silent: the conversion that needed the missing one
146//! cannot be built, and `build` names it.
147//!
148//! **Cycles** are the one place the order cannot be honoured: a self-referential
149//! type (`struct Node { next: Option<Box<Node>> }`) has none. `crossings` breaks
150//! such a cycle at its entry, so exactly one member is offered before an inner
151//! it contains. A generator that cannot build it omits it, and it is reported
152//! like any other gap.
153//!
154//! Direction is a **parameter**, never part of a name: [`Direction`] already
155//! carries it, and one `conversion(dir, ty)` cannot drift the way an
156//! `input_`/`output_` pair can — as `required_output_types`, which never grew an
157//! input peer, shows.

187/// Single owner of everything parsed from the prebindgen source stream.
188///
189/// Carries no adapter metadata. It used to be generic over one, so a converter's
190/// language-specific extras could be stored beside it and read back; an adapter
191/// keeps its own conversions now, so both the storage and the parameter are
192/// gone.
193pub struct Registry {
194    /// The parsed model these maps project. Held rather than discarded, so a
195    /// later stage can ask it what a name means through the registry it already
196    /// has — see [`Self::flat`].
197    flat: prebindgen_flat::flat::Flat,
198    /// What the binding declared, pushed in through `RegistryBuilder`'s
199    /// `export` / `export_type` / `cross` / `reference` before its `build`.
200    ///
201    /// Stored rather than asked for: the registry never calls the generator to
202    /// find out what to build. It is also read after resolution — `write`'s
203    /// emission gate is "did the binding declare this item" — so it outlives
204    /// the scan that consumes it.
205    declared: Declared,
206    /// Type tables, one per direction. Each scanned type gets a `TypeCell`
207    /// holding what the key names, whether the binding asks for it directly, and
208    /// the conversion once the generator supplies one.
209    ///
210    /// **Crate-internal.** Outside, a table is reached through
211    /// [`Conversions::conversion`] — which is what makes direction a parameter
212    /// rather than half of a field name, and what stops anyone observing a cell
213    /// before `RegistryBuilder::build` has graded it.
214    pub(crate) input_types: HashMap<TypeKey, TypeCell>,
215    pub(crate) output_types: HashMap<TypeKey, TypeCell>,
216
217    /// Resolved constructor-expansion plans, keyed by `(function, parameter)`.
218    /// Filled by [`crate::expand::apply`] before resolution; read
219    /// by language adapters at the parameter-emission site. Empty unless the
220    /// adapter declared expansions.
221    pub(crate) expansion_plans: HashMap<(syn::Ident, syn::Ident), crate::expand::FoldPlan>,
222
223    /// Resolved output-expansion plans, keyed by function ident. Filled by
224    /// [`crate::unfold::apply`] before resolution; read by language
225    /// adapters at the return-emission site. Empty unless the adapter declared
226    /// deconstructors.
227    pub(crate) unfold_plans: HashMap<syn::Ident, crate::unfold::UnfoldPlan>,
228
229    /// Resolved **error**-position expansion plans, keyed by function ident: the
230    /// decomposition of a fallible fn's `Result<_, E>` domain error `E` (from
231    /// `.convert_error` / `.deconstruct_error`). Separate from
232    /// [`Self::unfold_plans`] — a fn may have both an output and an error plan.
233    pub(crate) error_plans: HashMap<syn::Ident, crate::unfold::UnfoldPlan>,
234
235    /// Default decomposition of a **callback argument** type — the `T` of a
236    /// declared fn's `impl Fn(T, …)` parameter — keyed by the bare arg type
237    /// (type-level, fn-independent). Filled by
238    /// [`crate::unfold::apply`] from the type's default
239    /// deconstructor (`by_ref = false`: the trampoline owns the value); read by
240    /// language adapters when emitting the callback trampoline. A type without
241    /// a default deconstructor has no entry and is delivered whole.
242    pub(crate) callback_arg_plans: HashMap<TypeKey, crate::unfold::UnfoldPlan>,
243
244    /// The declaration-default decomposition per deconstructor declaration
245    /// ([`crate::unfold::DeconId`]) — resolved once with
246    /// normalized inputs, independent of using functions and processing
247    /// order. The single source language adapters derive declaration-keyed
248    /// signature artifacts (e.g. generated callback interfaces) from, so
249    /// every function selecting the same declaration sees one signature by
250    /// construction.
251    pub(crate) decon_plans: HashMap<crate::unfold::DeconId, crate::unfold::DeconSpec>,
252}

262impl Registry {
263    /// An empty registry: no model, no items, no types.
264    ///
265    /// **Not public.** A `Registry` is a projection of a [`Flat`](prebindgen_flat::Flat), and one built
266    /// this way projects nothing — [`Self::flat`] would hand a later stage an
267    /// empty model that claims to be this registry's source. Outside this crate
268    /// the entry point is [`Self::builder`], which has a model behind it.
269    /// `Self::empty` for the test suite of an out-of-crate adapter.
270    ///
271    /// Gated on the non-default `testing` feature, so the "not public" rule
272    /// above is unchanged for every ordinary build; a fixture that wants a
273    /// registry projecting nothing is the one caller it was never aimed at.
274    #[cfg(any(test, feature = "testing"))]
275    pub fn empty_for_test() -> Self {
276        Self::empty()
277    }
278
279    /// Whether `key` is registered in `dir`, and if so whether the binding
280    /// asked for it directly (the cell's root flag).
281    ///
282    /// Test support, `testing`-gated: it answers the one question a fixture
283    /// asks of a cell without handing out `TypeCell`, which is the
284    /// registry's storage and no part of the public surface.
285    #[cfg(any(test, feature = "testing"))]
286    pub fn is_root_for_test(&self, dir: Direction, key: &TypeKey) -> Option<bool> {
287        self.type_table(dir).get(key).map(|cell| cell.root)
288    }
289
290    /// Whether `key`'s cell in `dir` has been answered.
291    ///
292    /// Test support, `testing`-gated: a fixture that built the type itself
293    /// holds only its identity, and this is the one question about a cell that
294    /// does not need a reading.
295    #[cfg(any(test, feature = "testing"))]
296    pub fn has_entry_for_test(&self, dir: Direction, key: &TypeKey) -> Option<bool> {
297        self.type_table(dir)
298            .get(key)
299            .map(|cell| cell.entry.is_some())
300    }
301
302    /// The unfold plans built for callback arguments.
303    ///
304    /// Test support, `testing`-gated. [`UnfoldPlan`](crate::unfold::UnfoldPlan)
305    /// is already public, so this exposes no new type — only the map the
306    /// registry keeps them in.
307    #[cfg(any(test, feature = "testing"))]
308    pub fn callback_arg_plans_for_test(&self) -> impl Iterator<Item = &crate::unfold::UnfoldPlan> {
309        self.callback_arg_plans.values()
310    }
311
312    pub(crate) fn empty() -> Self {
313        Self {
314            flat: prebindgen_flat::flat::Flat::default(),
315            declared: Declared::default(),
316            input_types: Default::default(),
317            output_types: Default::default(),
318            expansion_plans: HashMap::new(),
319            unfold_plans: HashMap::new(),
320            error_plans: HashMap::new(),
321            callback_arg_plans: HashMap::new(),
322            decon_plans: HashMap::new(),
323        }
324    }
325}

327/// Everything the caller declares about what a binding emits.
328///
329/// **The registry's construction input.** It used to be assembled by calling
330/// twenty-one getters back into the adapter from inside `resolve`, which put
331/// "configuring" and "using" in the same call — and that is what let a converter
332/// read a half-built registry, which is what made `None` ambiguous between
333/// *defer* and *cannot*. The caller fills this first; `resolve` then passes or
334/// fails.
335#[derive(Default)]
336pub(crate) struct Declared {
337    pub(crate) functions: HashSet<syn::Ident>,
338    /// Signature-scanned but not emitted — see [`Prebindgen::helper_functions`].
339    pub(crate) helper_functions: HashSet<syn::Ident>,
340    pub(crate) accessors: HashSet<syn::Ident>,
341    pub(crate) method_receivers: HashMap<syn::Ident, TypeKey>,
342    /// Exported types, each **with the spelling its declaration was written
343    /// with**.
344    ///
345    /// Keyed by identity, because that is what a declaration is looked up by —
346    /// and carrying the `syn::Type` anyway, because the scan needs real tokens
347    /// for these: to `intern` a type that is not yet in any table, and to say
348    /// whether the build script path-qualified it. Recovering those *from the
349    /// key* was the wrong direction — a build script wrote a `syn::Type`, and
350    /// the declaration simply discarded it (#291).
351    pub(crate) types: HashMap<TypeKey, Origin<syn::Type>>,
352    /// Consts to scan and emit, or `None` when the adapter has no const
353    /// declaration mechanism — then every captured const is re-emitted
354    /// verbatim (see the const gate in [`crate::write`]).
355    ///
356    /// The two are identical for the *crossing set* — neither scans anything —
357    /// so this would be a plain `HashSet` if scanning were all it drove. It is
358    /// emission that needs the distinction, which is why the sentinel outlives
359    /// the skip warnings it also used to gate.
360    pub(crate) consts: Option<HashSet<syn::Ident>>,
361    /// Crossings with no `#[prebindgen]` element behind them, each in the one
362    /// direction it actually crosses — see [`Registry::cross`].
363    pub(crate) crossings: Vec<(Direction, syn::Type)>,
364    /// How composites cross in pieces — see [`Registry::decompose`].
365    pub(crate) decompositions: Decompositions,
366    /// Ordering edges no syntax shows — see [`Registry::depends`].
367    pub(crate) edges: Vec<(Crossing, Crossing)>,
368}

370/// How a binding's composites cross **in pieces** instead of whole.
371///
372/// One value, pushed once through `RegistryBuilder::decompose`, in place of the five
373/// separate hooks the registry used to call back for (`expansions`,
374/// `deconstructors`, `value_struct_decons`, `sum_decons`,
375/// `leaf_vec_fold_elements`). All five are implemented by one adapter and none
376/// of them ever needed more than the model, which is what makes stating them up
377/// front possible.
378///
379/// The fields are still the five declaration families, because unifying the
380/// plan IRs behind them is its own problem (see issue #223) and pretending
381/// otherwise here would only move the seam. What this settles is *when* they
382/// are stated and *by whom*.
383#[derive(Default)]
384pub struct Decompositions {
385    /// Parameter-side: values built on the Rust side from ingredients that
386    /// cross separately.
387    pub expansions: Option<crate::expand::Expansions>,
388    /// Return/error-side: values delivered as leaves the far side reassembles.
389    pub deconstructors: Option<crate::unfold::Deconstructors>,
390    /// By-value struct decompositions whose leaves the adapter computed.
391    pub value_structs: Vec<crate::unfold::ValueDecon>,
392    /// The selector-carrying sibling: a tag plus one leaf group per
393    /// alternative.
394    pub sums: Vec<crate::unfold::SumDecon>,
395    /// Element types of a `Vec<T>`/`&[T]` delivered element-by-element.
396    pub leaf_vec_elements: Vec<TypeKey>,
397    /// The whole-value crossings these decompositions make unnecessary.
398    ///
399    /// Stated **with** the decompositions rather than beside them: a type
400    /// crosses only in pieces *because* something decomposes it, and once the
401    /// plans are applied its own direct converter is genuinely not needed — for
402    /// a type with no destination representation, not even resolvable.
403    ///
404    /// Carries each declaration's own spelling for the same reason the declared
405    /// types do — these are build-script-authored types the scan diagnoses
406    /// before anything has classified them.
407    pub replaces: HashMap<TypeKey, Origin<syn::Type>>,
408}
