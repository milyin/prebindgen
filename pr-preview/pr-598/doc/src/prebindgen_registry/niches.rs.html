1//! Niche optimisation for FFI-wire encodings.
2//!
3//! A *niche* is a bit-pattern that the wire type *can* represent but that
4//! a particular converter is guaranteed to never produce on output and
5//! always reject on input. Wrappers like `Option<_>` and sum-typed enums
6//! carve niches one at a time for their own discriminants and re-export
7//! the remainder so further wrappers stack.
8//!
9//! Direct analogy with Rust's niche optimisation:
10//!
11//! | Rust                         | This crate                              |
12//! | ---------------------------- | --------------------------------------- |
13//! | `NonZeroU32` declares `{0}`  | converter sets `niches = Niches::one(…)`|
14//! | `Option<NonZeroU32>` is u32  | `Option<T>` reuses inner's wire         |
15//! | `Option<Option<NonZeroU32>>` | falls back unless inner exposes ≥2      |
16//!
17//! In the FFI setting the canonical example is a Rust value encoded as a
18//! raw `Box::into_raw` pointer carried over the wire as an integer handle:
19//! real `Box::into_raw` results are never `0`, so the converter declares
20//! the single niche `{0}`. `Option<T>` then automatically reuses the same
21//! integer wire with `0` meaning `None`, matching the C-pointer-with-null
22//! ABI most native bindings already use.
23//!
24//! ## Aligned pointer tags
25//!
26//! Alignment can leave more invalid integer encodings than the null pointer.
27//! If generated Rust proves `align_of::<T>() >= 2`, every live
28//! `Box::into_raw` pointer to `T` has bit zero clear. An adapter can reserve
29//! that bit as an out-of-band tag while carrying the pointer in an integer
30//! wire.
31//!
32//! JniGen uses exactly this scheme for handle invalidation:
33//!
34//! | integer handle | meaning |
35//! |---|---|
36//! | `0` | an absent optional handle |
37//! | nonzero, even | a live `Box<T>` pointer |
38//! | nonzero, odd | a closed handle; the original address is `v & !1` |
39//!
40//! Closing a Kotlin handle sets bit zero instead of replacing the address, so
41//! the masked address remains an immutable lock-ordering key. Generated Rust
42//! asserts the alignment floor and rejects an odd value before any dereference.
43//!
44//! The odd encodings are **not** entries in JniGen's [`Niches`]. They already
45//! mean “closed handle”, an operational error that can reach the decoder; if
46//! an `Option` layer carved one, a close race would silently become `None`.
47//! “Not a valid live pointer” is therefore insufficient to make an encoding a
48//! representation niche. A slot belongs in [`Niches`] only when the wrapper is
49//! free to claim its meaning.
50//!
51//! An adapter reusing aligned-pointer tags must keep the complete protocol
52//! together:
53//!
54//! 1. assert the required alignment against the final concrete pointee type;
55//! 2. assign every reserved tag one meaning on both sides of the boundary;
56//! 3. recognize tags before dereferencing or freeing the integer as a pointer;
57//! 4. mask tags anywhere the stable address identity is compared or ordered;
58//! 5. publish only genuinely unclaimed encodings as [`NicheSlot`]s.
59//!
60//! Reserving several low-bit patterns requires a correspondingly stronger
61//! alignment guarantee and a non-overlapping allocation between lifecycle
62//! tags and wrapper discriminants.
63//!
64//! ## Cascading
65//!
66//! [`Niches::carve`] returns the next slot together with the remainder.
67//! The wrapper places the carved value into its own emitted code (output:
68//! `None` is encoded as `slot.value`; input: `slot.matches` is the
69//! discriminator predicate) and stores `rest` on its own
70//! [`crate::prebindgen::ConverterImpl::niches`] so any
71//! enclosing wrapper can keep carving. Once `rest` is empty further
72//! wrappers must fall back to a tag/box scheme.
73//!
74//! ## Soundness
75//!
76//! For the carve to be sound, the inner converter's outputs must
77//! genuinely avoid the carved bit pattern, and its input must reject it
78//! (typically by erroring). The adapter author guarantees this — `Niches`
79//! is a *declaration* that the resolver and wrappers trust.
80//!
81//! ## Calling convention for `matches`
82//!
83//! The `matches` predicate is spliced into the input wrapper's body where
84//! the wire-typed parameter `v` is in scope. The exact shape of `v`
85//! depends on the wire kind:
86//!
87//! * By-reference wires (e.g. an integer handle, or an object-handle
88//!   type): `v: &<wire>` — write `*v == 0`, or `v.is_null()` for a handle
89//!   type that derefs to a null check.
90//! * Raw-pointer wires (`*const T`): `v: <wire>` — write `v.is_null()`
91//!   directly, no `*` deref.
92//!
93//! The adapter producing the niche knows which wire kind it is using and
94//! must write `matches` accordingly.
95//!
96//! `value` is a wire-typed *constant* expression with no `v` and no other
97//! locals in scope — just the bit pattern (e.g. `0i64`,
98//! `std::ptr::null()`).
99
100/// One free bit-pattern slot in the wire encoding.
101///
102/// See the module-level docs for the calling convention of `matches` and
103/// `value`.
104#[derive(Clone)]
105pub struct NicheSlot {
106    /// Wire-typed constant expression evaluating to this niche's bit
107    /// pattern. Used by output wrappers to emit the discriminant.
108    pub value: syn::Expr,
109    /// Predicate testing whether the wire value `v` (in the local
110    /// wrapper convention — see module docs) is *this* slot. Used by
111    /// input wrappers to detect the discriminant.
112    pub matches: syn::Expr,
113}
114
115/// An ordered set of [`NicheSlot`]s that a converter's wire type can
116/// represent but that this converter never produces (output) and always
117/// rejects (input).
118///
119/// Ordering: the *first* slot is the next one taken by [`Self::carve`].
120/// Wrappers carve from the front; the remaining slots are passed up so
121/// that further wrappers can stack their own discriminants.
122#[derive(Clone, Default)]
123pub struct Niches {
124    pub slots: Vec<NicheSlot>,
125}
126
127impl Niches {
128    /// No free bit-patterns. The default for converters whose wire
129    /// encoding uses every bit-pattern as a valid value (e.g. a plain
130    /// `i64` wire).
131    pub fn empty() -> Self {
132        Self::default()
133    }
134
135    /// Convenience for the common single-niche case.
136    pub fn one(value: syn::Expr, matches: syn::Expr) -> Self {
137        Self {
138            slots: vec![NicheSlot { value, matches }],
139        }
140    }
141
142    /// Build from any iterable of slots; ordering is preserved.
143    pub fn from_slots<I: IntoIterator<Item = NicheSlot>>(slots: I) -> Self {
144        Self {
145            slots: slots.into_iter().collect(),
146        }
147    }
148
149    /// Take the first slot for use as a wrapper's discriminant. Returns
150    /// the carved slot and the remaining niches (which the wrapper
151    /// should re-export on its own
152    /// [`ConverterImpl`](crate::prebindgen::ConverterImpl)).
153    /// `None` if the
154    /// set is empty — the caller must fall back to a tag/box scheme.
155    pub fn carve(mut self) -> Option<(NicheSlot, Niches)> {
156        if self.slots.is_empty() {
157            None
158        } else {
159            let head = self.slots.remove(0);
160            Some((head, self))
161        }
162    }
163
164    pub fn len(&self) -> usize {
165        self.slots.len()
166    }
167
168    pub fn is_empty(&self) -> bool {
169        self.slots.is_empty()
170    }
171}
