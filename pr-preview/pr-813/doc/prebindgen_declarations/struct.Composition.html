Expand description

Describes how a conversion’s FFI values fit together.

A conversion plan has a list of wires: the individual values passed across the FFI boundary. This metadata explains how to interpret those values together. It is stored in InputPlan::metadata or OutputPlan::metadata and is used while generating bindings; it is not passed across the FFI boundary.

For example, C can represent an Option<i32> with two wires:

present: int32_t    0 for None, 1 for Some
value:   int32_t    the integer inside Some; ignored for None

A group is a named description of the wires that together represent a value. For this example, one optional group lists present and value, says that present decides between None and Some, and identifies value as the payload. The C adapter uses that information to document the arguments; the JNI adapter uses optional groups to generate nullable Kotlin parameters and results where possible.

Groups can contain other groups. For example, an optional record can have an outer group describing whether the record is present and a child group describing how its fields form the record. groups stores all these descriptions by name. roots lists the groups that have no parent. Groups refer to wires by name; the wires stay in the plan’s list.

Some types have a niche: an otherwise unused representation that can stand for None without adding a presence flag. For example, C uses 0x110000, which is not a valid Rust char, for None in Option<char>. Once that value is taken, an enclosing option needs a different unused value or a flag. domains records which niche, if any, each wire can still offer to an enclosing option. It does not describe the wire’s full set of valid values.

N is the adapter’s description of a niche. G holds information for groups specific to an adapter, such as the Kotlin class to construct from record fields. Use () for either type when that information is not needed.

Fields§

§groups: BTreeMap<String, CompositionGroup<N, G>>

Every group in this conversion, including nested groups, indexed by name. Each entry describes which wires represent a value and how to interpret them.

§roots: Vec<String>

Names of the groups that are not children of another group. They appear in the same order as their wires in the plan. A wire that needs no grouping can be omitted from all groups; it needs no entry here.

§domains: BTreeMap<String, Option<N>>

Whether each wire may supply an unused representation for another Option. Keys are wire names. The three cases mean:

  • No entry: ask Codec::niche what the wire’s type offers.
  • Some(n): use n as the next unused representation for None.
  • None: do not use this wire to encode another None.

For example, after Option<char> reserves 0x110000 on a C wire named value, its entry offers 0x110001 for an enclosing option. Other wires in the same optional value get None: their defaults for an absent value must not accidentally be used to distinguish another option layer.

pub fn suppress<W: WireKind>(&mut self, wires: &[Wire<W>])

Prevent enclosing options from using these wires to encode None.

Writes None to their domains entries. For example, a wire used only in one constructor alternative cannot tell us whether the whole optional input is present when another alternative is selected.

Source

pub fn enclose( &mut self, name: String, members: Vec<Ident>, kind: GroupKind<N, G>, ) -> Result<()>

Add a parent group around the groups currently listed in roots.

Those groups become its children, and roots becomes just [name]. members must name all wires belonging to the new parent, including its children’s wires. Returns an error if name already identifies a group.

Source

pub fn starting_at( &self, roots: &[String], name: &Ident, ) -> Option<&CompositionGroup<N, G>>

Among the supplied group names, find the group whose first wire is name.

Pass roots to search the outermost groups, or a group’s children to search immediately inside it. This does not search descendants.

Source

pub fn validate<W: WireKind>(&self, wires: &[Wire<W>]) -> Result<()>

Check that these descriptions agree with the conversion plan’s wire list.

Rejects duplicate wire names, missing references, empty groups, cycles and groups whose wires are not consecutive or in order. Also checks that each optional group’s flag or niche wire and payload belong to that group. Wires without a group are allowed.
