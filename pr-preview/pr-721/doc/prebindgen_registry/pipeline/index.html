The flat model itself lives in the separate prebindgen-flat crate — re-exported here so an adapter names one crate root for the whole pipeline. RustEmitter is deliberately omitted: registry-only adapters receive final rendering authority as RustWriter in callbacks. A different collector depends on prebindgen-flat directly to implement its own key. Which generation engine a build script runs.

There are two: v1, the engine every adapter ships today, and v2, the parallel engine of #719. Both read the same declarations; a build script picks one, and the pick is made once, at the final .build(), before either engine plans anything.

Two things decide it, and they are deliberately different questions:

  • Availability is a compile-time fact — the adapter’s optional v2 Cargo feature. An environment variable cannot enable a dependency after compilation has started, so a v2 run needs --features v2 on the Cargo command as well as the selector below.
  • Selection is a build-time fact — PREBINDGEN_PIPELINE=v1|v2, read at dispatch. Unset means v1, including under --all-features: enabling the feature makes v2 available and never selects it.

Pipeline::resolve is the one validator both routes go through — the environment (.build()) and an explicit request (.build_with(..)).
