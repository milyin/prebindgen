1//! What the engine asks a language adapter, and the shapes it answers in.
2//!
3//! Four planning questions — [`Target::select`], [`Target::represent`],
4//! [`Target::boundary`], [`Target::surface`] — plus one rendering call,
5//! [`Target::render_operation`]. Each planning answer is local: it describes
6//! *this* value, *this* call, *this* declaration. The recursion that visits a
7//! struct's fields, the locals, the branches and the wrapper around them all
8//! belong to the registry, which is why a nested struct costs an adapter
9//! nothing.
10//!
11//! Everything here is a **description**. Nothing an adapter returns is
12//! generated text except [`Target::render_operation`]'s single expression and
13//! the [`Artifact`]s it contributes whole.
14//!
15//! # The words the doc comments use
16//!
17//! - The **binding** is the crate a user builds and ships — `zenoh-flat-c`,
18//!   `zenoh-flat-jni` — whose `build.rs` declares what to expose. It is the
19//!   consumer of everything here.
20//! - The **target** is a language together with the calling interface it
21//!   reaches Rust through — C, or Kotlin through JNI — and, in code, the
22//!   adapter implementing [`Target`] for it. The same crate is the
23//!   **frontend** when it faces the binding's `build.rs`, and the target
24//!   adapter when it faces the registry.
25//! - The **registry** is this crate: it plans and asks; the target answers.
26//! - A **source function** is a Rust function in the source crate — the
27//!   `#[prebindgen]`-marked crate the captures come from — that the binding
28//!   asked to expose, with `fun!(ledger_open)` or the like. It is never
29//!   exported itself; it stays where it is and is called. An **exported
30//!   function**, or **wrapper**, is the Rust function the registry generates
31//!   around it: one the target's calling interface can reach, which converts
32//!   what arrives, calls the source function once, and converts what it
33//!   returns. The writer renders every wrapper as an `extern` function under a
34//!   `#[no_mangle]` symbol; what a target decides of its form is in
35//!   [`AbiSpec`] — the convention, the symbol, the signature, its attributes
36//!   and whether it is `unsafe`. A binding exports only wrappers.
37//! - The **wrapper boundary** is the form the wrapper is called through: its
38//!   calling convention, symbol, parameters and return. A **wrapper
39//!   parameter** is one of those parameters, spelled as a `jlong` or a
40//!   `*mut ledger_t`. Everything on the other side of that boundary — the
41//!   Kotlin function that calls the wrapper, the C prototype a caller
42//!   compiles against — is the **foreign** or **public** side.
43//!
44//! This is the first increment (docs/v2). What it carries is the scalar, the
45//! owned struct and the owned opaque handle; the fields the chapters describe
46//! for resources, validity and sequences arrive with the capabilities that need
47//! them, and `docs/v2/implementation.md` lists exactly what is absent.
48

142/// One field of a struct relation, or one argument of a constructor relation.
143#[derive(Clone, Debug)]
144pub struct Part {
145    /// The field's name, absent for a positional field.
146    pub name: Option<String>,
147    /// Its position in the relation, which is its identity when it has no name.
148    pub index: usize,
149    /// Its exact source type.
150    pub ty: TypeRef,
151    /// The `#[cfg]` conditions the source field was written under, which the
152    /// capture reader could not answer — empty in the ordinary case.
153    ///
154    /// A target re-declaring this part as a member of its own struct puts them
155    /// on that member. It must not read them: the registry puts the same
156    /// conditions on every instruction that serves this part, so a member
157    /// declared under them is read under them.
158    pub conditions: Vec<TokenStream>,
159}
160
161impl Part {
162    /// How a diagnostic and a target's configuration address this part.
163    pub fn label(&self) -> String {
164        match &self.name {
165            Some(name) => name.clone(),
166            None => self.index.to_string(),
167        }
168    }
169}

215/// A registered target/intermediate carrier type.
216///

257/// Where an operand's value comes from.
258///
259/// A runtime context — the JNI environment — is an operand like any other, so

270    Error,
271}

349/// An operation the registry itself knows how to render, so a target that
350/// needs one ships no renderer for it.
351///
352/// The three handle operations are here because they are Rust, not C or JNI:
353/// moving a source value onto the heap and back is the same for every target,
354/// and it is the one place a conversion has to spell a *source* type — which
355/// only the registry may do. What differs per target is the carrier the
356/// address is cast to, and that the target states.
357#[derive(Clone, Debug)]
358pub enum StandardOp {
359    /// The result *is* the operand: the carrier and the source value are one
360    /// Rust value. Renders nothing at all.
361    Identity,
362    /// Read a member of an aggregate carrier: `arg0.secs`.
363    ReadMember { member: syn::Member },
364    /// Hand an owned source value to the foreign side as an address:
365    /// `Box::into_raw(Box::new(v)) as <carrier>`. The foreign side owns the
366    /// allocation from here on.
367    IntoRaw { carrier: Box<syn::Type> },
368    /// Take back what [`StandardOp::IntoRaw`] handed out:
369    /// `*Box::from_raw(v as *mut <source>)`. A null address is a binding
370    /// failure carrying a `String`; the handle is consumed either way.
371    FromRaw { source: Box<TypeRef> },
372    /// Drop what [`StandardOp::IntoRaw`] handed out without converting it. A
373    /// null address releases nothing, as `free(NULL)` does. Produces no value.
374    Release { source: Box<TypeRef> },
375}
376
377/// What actually performs an operation.
378///
379/// This is the settled form of the chapters' open question about
380/// registry-supplied operations inside an adapter's payload: a payload is the
381/// adapter's own type, and the standard operations are a variant beside it
382/// rather than something an adapter has to encode.
383#[derive(Clone, Debug)]
384pub enum Operation<P> {
385    Standard(StandardOp),
386    Target(P),
387}
388
389/// One typed operation supplied by a target.
390///
391/// It describes an operation, not a use of one: it names no variable and
392/// belongs to no wrapper, so the same description is applied wherever the
393/// operation is needed.
394#[derive(Clone, Debug)]
395pub struct PrimitiveSpec<P> {
396    pub operands: Vec<OperandSpec>,
397    /// The value available after success, or nothing for an operation that
398    /// produces none.
399    pub result: Option<OperationType>,
400    pub failure: PrimitiveFailure,
401    /// Generated units this operation needs in order to compile.
402    pub dependencies: Vec<Artifact>,
403    pub implementation: Operation<P>,
404}
405
406impl<P> PrimitiveSpec<P> {
407    /// The conversion that renders nothing: the carrier already *is* the source
408    /// value.
409    pub fn identity(ty: OperationType) -> Self {
410        PrimitiveSpec {
411            operands: vec![OperandSpec::value(ty.clone(), Access::Owned)],
412            result: Some(ty),
413            failure: PrimitiveFailure::Infallible,
414            dependencies: Vec::new(),
415            implementation: Operation::Standard(StandardOp::Identity),
416        }
417    }
418
419    /// Hand an owned `source` value out as `carrier` — see
420    /// [`StandardOp::IntoRaw`]. Infallible.
421    pub fn into_raw(source: TypeRef, carrier: WireType) -> Self {
422        PrimitiveSpec {
423            operands: vec![OperandSpec::value(
424                OperationType::Source(source),
425                Access::Owned,
426            )],
427            result: Some(OperationType::Carrier(carrier.clone())),
428            failure: PrimitiveFailure::Infallible,
429            dependencies: Vec::new(),
430            implementation: Operation::Standard(StandardOp::IntoRaw {
431                carrier: Box::new(carrier.ty),
432            }),
433        }
434    }
435
436    /// Take an owned `source` value back from `carrier` — see
437    /// [`StandardOp::FromRaw`]. Fails with a `String` in the binding category
438    /// when the address is null, so a boundary passing handles needs a route
439    /// for that category.
440    pub fn from_raw(carrier: WireType, source: TypeRef) -> Self {
441        PrimitiveSpec {
442            operands: vec![OperandSpec::value(
443                OperationType::Carrier(carrier),
444                Access::Owned,
445            )],
446            result: Some(OperationType::Source(source.clone())),
447            failure: PrimitiveFailure::fallible(
448                OperationType::Carrier(WireType::internal(syn::parse_quote!(String))),
449                FailureCategory::Binding,
450            ),
451            dependencies: Vec::new(),
452            implementation: Operation::Standard(StandardOp::FromRaw {
453                source: Box::new(source),
454            }),
455        }
456    }
457
458    /// Drop a `source` value held behind `carrier` — see
459    /// [`StandardOp::Release`]. Infallible, produces nothing.
460    pub fn release(carrier: WireType, source: TypeRef) -> Self {
461        PrimitiveSpec {
462            operands: vec![OperandSpec::value(
463                OperationType::Carrier(carrier),
464                Access::Owned,
465            )],
466            result: None,
467            failure: PrimitiveFailure::Infallible,
468            dependencies: Vec::new(),
469            implementation: Operation::Standard(StandardOp::Release {
470                source: Box::new(source),
471            }),
472        }
473    }
474
475    /// How many operands this application takes from the enclosing conversion.
476    pub(crate) fn value_operands(&self) -> usize {
477        self.operands
478            .iter()
479            .filter(|operand| matches!(operand.role, OperandRole::Value))
480            .count()
481    }
482
483    /// Whether this application consumes the value it is given.
484    pub(crate) fn consumes_value(&self) -> bool {
485        self.operands.iter().any(|operand| {
486            matches!(operand.role, OperandRole::Value) && operand.access == Access::Owned
487        })
488    }
489
490    pub(crate) fn failure_category(&self) -> Option<FailureCategory> {
491        match &self.failure {
492            PrimitiveFailure::Infallible => None,
493            PrimitiveFailure::Fallible { category, .. } => Some(*category),
494        }
495    }
496}

605/// The boundary of one exported function: how the wrapper the
606/// registry generates around a source function is reached from the target's
607/// side.
608///
609/// The writer renders every wrapper as
610/// `#[no_mangle] <attrs> pub <unsafe> extern "<abi>" fn <symbol>(<params>) -> <ret>`,
611/// and everything in angle brackets is the target's to decide here. The
612/// `#[no_mangle]`, the `pub` and the `fn` are the writer's: a wrapper is
613/// reached by its symbol, and a target that needed another linkage would need
614/// a variant of this type rather than an attribute that fights the one the
615/// writer adds — which the registry refuses (see [`AbiSpec::attrs`]).
616///
617/// This is the specification's `AbiSpec<Payload>` with the payload made
618/// concrete: the "target signature requirements" the chapter leaves open are
619/// the attributes and the safety of the signature, because those are what the
620/// writer has to render and can check, and what V1's JNI wrapper —
621/// `#[allow(..)] pub unsafe extern "C"` — needs beyond the convention and
622/// the symbol.
623#[derive(Clone, Debug)]
624pub struct AbiSpec {
625    /// The `extern` string: `"C"`, `"system"`.
626    pub abi: String,
627    /// The symbol the wrapper is exported under, which the foreign side links
628    /// against. Not the source function's name: the frontend's naming settled
629    /// it.
630    pub symbol: String,
631    /// The wrapper's parameters, in boundary order — the ones serving a source
632    /// parameter and the ones the calling convention adds.
633    pub params: Vec<WrapperParam>,
634    /// The wrapper's return type, absent when it returns nothing.
635    pub ret: Option<WireType>,
636    /// Attributes the wrapper carries beyond `#[no_mangle]`, rendered after
637    /// it: a lint the generated signature would otherwise trip
638    /// (`#[allow(non_snake_case)]`), a target's own marker. Empty for both
639    /// targets today.
640    ///
641    /// Linkage is not the target's to restate: `#[no_mangle]` and
642    /// `#[export_name]` here are contradictory input and fail the build, since
643    /// the writer already exports the wrapper under [`AbiSpec::symbol`].
644    pub attrs: Vec<syn::Attribute>,
645    /// Whether the wrapper is an `unsafe fn`. `false` for both targets today:
646    /// the wrapper checks what it is handed, and a caller owes it nothing a
647    /// safe function cannot state. A convention that makes the caller
648    /// responsible for the pointers it passes says so here, and the foreign
649    /// declaration should say the same.
650    pub unsafety: bool,
651}

705/// emitted too. A target states that with the type, not with the id of the
706/// declaration representing it: at [`Target::surface`] it holds the model's
707/// answer about a value, not the binding's declaration of a type, and the
708/// engine is the side that knows which declaration covers which type.
709#[derive(Clone, Debug, PartialEq, Eq)]
710pub struct Requirement {
711    type_name: String,
712}
713
714impl Requirement {
715    /// What `ty` requires, if it names a type at all — `None` for a scalar or
716    /// anything else with no declared type of its own.
717    pub fn of(ty: &TypeRef) -> Option<Self> {
718        match ty.kind() {
719            TypeKind::Named { id, .. } => Some(Requirement {
720                type_name: id.name.clone(),
721            }),
722            _ => None,
723        }
724    }
725
726    /// The same for a type the target knows by name without holding a
727    /// reference to it.
728    pub fn type_named(name: impl Into<String>) -> Self {
729        Requirement {
730            type_name: name.into(),
731        }
732    }
733
734    /// The type's name, as the model spells it.
735    pub fn type_name(&self) -> &str {
736        &self.type_name
737    }
738}
739
740impl std::fmt::Display for Requirement {
741    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
742        write!(f, "type `{}`", self.type_name)
743    }
744}

764/// Where a conversion sits: what a target looks a per-site choice up by, and
765/// what a diagnostic prints.
766#[derive(Clone, Debug, PartialEq, Eq, Hash, PartialOrd, Ord)]
767pub struct Position {
768    /// The requested output this conversion is reached from.
769    pub declaration: Declaration,
770    /// Root to here: `param 0`, then `field secs`.
771    pub path: Vec<String>,
772}
773
774impl Position {
775    pub fn root(declaration: Declaration) -> Self {
776        Position {
777            declaration,
778            path: Vec::new(),
779        }
780    }
781
782    pub fn child(&self, step: impl Into<String>) -> Self {
783        let mut path = self.path.clone();
784        path.push(step.into());
785        Position {
786            declaration: self.declaration.clone(),
787            path,
788        }
789    }

791    /// This position as a report's dependency path.
792    pub fn dependency_path(&self) -> Vec<String> {
793        std::iter::once(self.declaration.to_string())

795            .collect()
796    }

799/// What `select` is given: the value, where it sits, and the relations
800/// available for it.
801///
802/// No configuration comes with it. Which settings apply to this value is the
803/// target's own lookup, over its own storage, from the type in
804/// [`Crossing::ty`] and the [`Position`] — which is how a choice recorded for
805/// one parameter of one function differs from the type's default.
806pub struct SelectionQuery<'a> {
807    pub crossing: &'a Crossing,
808    pub position: &'a Position,
809    /// The relations registered for this type: the implicit one, plus any the
810    /// configuration declared. A target picks one; it does not invent one.
811    ///
812    /// There is one per type today, because every relation the increment has is
813    /// implicit. Pinning a relation against the target's choice arrives with the
814    /// second kind — a declared constructor — since with one candidate there is
815    /// nothing to pin.
816    pub candidates: &'a [(RelationId, Relation)],
817}
818
819/// What `select` answers: how this value is read, and which conversion that
820/// makes it.
821///
822/// The `conversion` key is the target's own name for the settings it just
823/// applied. The registry never looks inside it; it compares keys, and two
824/// values whose crossing, relation, children and key are all equal share one
825/// conversion. So a key has one obligation, stated in #766: **equal keys mean
826/// interchangeable conversions** — same layout, same operations, same
827/// failures, same release. A target that minted a fresh key per visit would
828/// share nothing and would defeat cycle detection; one that returned an equal
829/// key for two settings that generate differently would silently give the
830/// second value the first one's conversion.
831#[derive(Clone, Debug, PartialEq, Eq, Hash)]
832pub struct Selection<K> {
833    /// One of the [`SelectionQuery::candidates`], by identity.
834    pub relation: RelationId,
835    /// What the target decided this value converts by.
836    pub conversion: K,
837}
838
839/// What `represent` is given: the selected relation, resolved against the
840/// model.
841///
842/// No position, deliberately. A representation is reused wherever a conversion
843/// with the same identity is needed, and that identity is the crossing, the
844/// relation, the [`Selection::conversion`] key and the children — a target
845/// that could answer differently for two positions would have its second
846/// answer silently bypassed. Varying by position is done in
847/// [`Target::select`], which does see one: it returns a different key, and a
848/// different key is a different conversion.
849pub struct ResolvedShape<'a> {
850    pub crossing: &'a Crossing,
851    pub relation: &'a Relation,
852    /// The struct behind a struct relation, for a target that renders its own
853    /// declaration of it.
854    pub strukt: Option<&'a Struct>,
855}

857/// One already-planned child, as its parent's representation sees it.
858pub struct ChildValue<'a> {
859    pub part: &'a Part,
860    pub layout: &'a Layout,
861}

863/// The planned conversions of one source function's parameters and result,
864/// as the boundary and the public declaration see them.
865///
866/// A wrapper is these conversions around one call: each input is converted
867/// from what the wrapper parameter carries, the source function is called,
868/// and its result is converted for delivery. What the target reads here is
869/// each plan's carrier — the layout a wrapper parameter or return must match —
870/// and the failure categories the boundary has to route.
871pub struct ResolvedValues<'a, P> {
872    /// One plan per source parameter, in [`Function::params`] order, each
873    /// crossing into Rust.
874    pub inputs: Vec<&'a crate::plan::ValuePlan<P>>,
875    /// The plan for the source function's result, crossing out of Rust, or
876    /// `None` when it returns nothing.
877    pub output: Option<&'a crate::plan::ValuePlan<P>>,
878}
879
880impl<P> ResolvedValues<'_, P> {
881    /// Every failure category the planned conversions can raise, sorted.
882    pub fn failure_categories(&self) -> Vec<FailureCategory> {
883        let mut categories: Vec<_> = self
884            .inputs
885            .iter()
886            .chain(self.output.iter())
887            .flat_map(|value| value.failures.iter().copied())
888            .collect();
889        categories.sort();
890        categories.dedup();
891        categories
892    }
893}

895/// The first argument of [`Target::boundary`]: which wrapper the call is about.
896///
897/// For every wrapper it builds, the registry calls
898/// `target.boundary(&site, &values)` once, and the target returns
899/// the wrapper's shape — symbol, calling convention, parameters,
900/// failure routes — as a [`BoundarySpec`], wrapped in [`TargetSupport`]: a
901/// spec, a reason the target cannot shape this one, or an error. `site` is
902/// this type and says which source function the wrapper exports: the
903/// declaration that requested the export, and the function itself. `values`
904/// is the [`ResolvedValues`] the wrapper converts. What the binding asked for
905/// — the exported symbol, where the public declaration lands — the target
906/// looks up in its own storage, by [`SiteDescriptor::declaration`].
907///
908/// What a target reads from the descriptor: the declaration, for the names in
909/// its refusals and errors; the source function's parameter list, for the
910/// names the wrapper signature keeps; and whether a source function is there
911/// at all. A descriptor with none says the wrapper is a handle's release —
912/// it takes the handle back and drops it (see [`ReprSpec::release`]) — and
913/// its declaration is the handle *type's*, so the target shapes it from what
914/// it recorded for that type rather than for a function.
915///
916/// Named after the specification's *site*, a value's position in an exported
917/// function: the boundary places each such position on a wrapper parameter or
918/// the return, and this identifies the function the positions belong to.
919pub struct SiteDescriptor<'a> {
920    /// The export this wrapper is for. For a release, the handle type's own
921    /// declaration — and what the target looks its configuration for this
922    /// wrapper up by. The exported symbol is not spelled here; the frontend
923    /// settled it when it recorded the declaration.
924    pub declaration: &'a Declaration,
925    /// The source function the wrapper calls once, or `None` for a release.
926    ///
927    /// The target reads its parameter *names*: a wrapper parameter keeps its
928    /// source parameter's name, and one the target adds — a JNI environment,
929    /// a receiver — is named around those. The parameter *types* come from
930    /// the plans in [`ResolvedValues::inputs`], which are in
931    /// [`Function::params`] order.
932    pub function: Option<&'a Function>,
933}
934
935/// What `surface` is given: the requested public declaration.
936///
937/// [`Self::declaration`] is what the target looks its own configuration for
938/// this output up by — which class or C name it was declared under, which
939/// declarator it came from.
940pub struct SurfaceRequest<'a> {
941    pub declaration: &'a Declaration,
942    pub item: SourceItem<'a>,
943}
944
945impl SurfaceRequest<'_> {
946    /// The `#[cfg]` conditions the captured item behind this request was
947    /// written under, spelled as the source wrote them — empty in the ordinary
948    /// case.
949    ///
950    /// Text rather than tokens, because the registry is what puts a condition
951    /// on the Rust it emits for this declaration. What is left for a target is
952    /// the declaration written in *its* language, which usually cannot state a
953    /// condition at all; saying so in that declaration's documentation is the
954    /// most such a target can do, and is better than saying nothing.
955    pub fn item_conditions(&self) -> Vec<String> {
956        let conditions = match self.item {
957            SourceItem::Struct(strukt) => {
958                crate::emit::Writer.conditions(Conditioned::Struct(strukt))
959            }
960            SourceItem::Function(function) => {
961                crate::emit::Writer.conditions(Conditioned::Function(function))
962            }
963            SourceItem::Extern(opaque) => {
964                crate::emit::Writer.conditions(Conditioned::Extern(opaque))
965            }
966        };
967        conditions
968            .iter()
969            .map(|condition| prebindgen_flat::close_up(&condition.to_string()))
970            .collect()
971    }
972
973    /// The `#[cfg]` conditions of each field of the struct behind this request,
974    /// in field order — empty entries for the ordinary unconditional field, and
975    /// an empty list for a request that is not a struct.
976    ///
977    /// A target declaring a member per field puts its entry on that member. The
978    /// registry puts the same conditions on every instruction that serves the
979    /// field, so a member declared under them is read under them and the
980    /// initializer that consumes the read is written under them too.
981    ///
982    /// Tokens rather than text, unlike [`Self::item_conditions`]: these go into
983    /// the Rust a target contributes.
984    pub fn field_conditions(&self) -> Vec<Vec<TokenStream>> {
985        match self.item {
986            SourceItem::Struct(strukt) => strukt
987                .fields
988                .iter()
989                .map(|field| crate::emit::Writer.conditions(Conditioned::Field(field)))
990                .collect(),
991            SourceItem::Function(_) | SourceItem::Extern(_) => Vec::new(),
992        }
993    }
994}

996/// The captured item a public declaration is made from, as the source model
997/// describes it.
998///
999/// A binding asks for an output by name — a [`Declaration`] such as
1000/// `type:Ledger` — and the registry resolves that name in the source model
1001/// before it plans anything. This is what it found: the model's own element,
1002/// borrowed from the [`Flat`] the run was planned over. A target receives it
1003/// as [`SurfaceRequest::item`] when it answers [`Target::surface`].
1004///
1005/// It is a view over the model and carries nothing of its own. What it adds
1006/// is shape: [`Element`] has variants no declaration can resolve to (a guard,
1007/// an unsupported item) and nests the type kinds one level down, so a target
1008/// matching on it would carry unreachable arms and a second match. This lists
1009/// exactly the kinds a resolved declaration can be — a constant and the enums
1010/// will add variants — so an adapter's `match` is exhaustive over real cases
1011/// and the compiler says when a kind is added.
1012///
1013/// The variant is a fact about the source, not about the representation: a
1014/// struct declared to C as an opaque pointer still arrives as
1015/// [`SourceItem::Struct`], and how the target carries it is in the target's
1016/// own configuration, under [`SurfaceRequest::declaration`]. Read that first.
1017/// A declaration the binding defines itself
1018/// ([`Declaration::is_binding_local`]) names no captured item and is refused
1019/// before `surface` is asked, so nothing here is ever absent.
1020///
1021/// [`Flat`]: prebindgen_flat::flat::Flat
1022/// [`Element`]: prebindgen_flat::flat::Element
1023/// [`Declaration::is_binding_local`]: crate::decl::Declaration::is_binding_local
1024#[derive(Clone, Copy)]
1025pub enum SourceItem<'a> {
1026    /// A captured free function, the item behind a `fn:` declaration.
1027    ///
1028    /// The target reads its signature — [`Function::params`] and
1029    /// [`Function::ret`] — to spell the foreign declaration, and pairs each
1030    /// parameter with the already-planned conversion the registry hands over
1031    /// in [`ResolvedValues::inputs`], in the same order. The call itself is
1032    /// not the target's business: the registry places it when it assembles
1033    /// the wrapper, from the [`SiteDescriptor`] it asked [`Target::boundary`]
1034    /// about.
1035    Function(&'a Function),
1036    /// A captured struct with fields the model can inspect, the usual item
1037    /// behind a `type:` declaration.
1038    ///
1039    /// A target declaring one — a `repr(C)` mirror, a Kotlin `data class` —
1040    /// re-declares its fields: [`Struct::fields`], with the `#[cfg]`
1041    /// condition of each in [`SurfaceRequest::field_conditions`]. A struct
1042    /// the binding declared to be carried whole crosses as a handle instead,
1043    /// and its fields go unread; the target learns that from its own
1044    /// configuration, not from this variant. A tuple struct is not this
1045    /// variant at all: its fields are not modelled, and the model declares it
1046    /// as [`SourceItem::Extern`].
1047    Struct(&'a Struct),
1048    /// A captured declaration with nothing behind it — a marked type alias
1049    /// such as `pub type Ledger = crate::ledger::Ledger;`, or a tuple struct —
1050    /// which the source model calls an extern.
1051    ///
1052    /// It has no parts to convert through, so a value of it crosses whole: as
1053    /// an opaque handle, represented by a carrier for the address and a
1054    /// release for it (see [`ReprSpec::release`]). [`Extern::target`]
1055    /// says what the alias pointed at, as text, for a target that wants to
1056    /// recognise one; the model does not classify it. A target with no handle
1057    /// representation refuses this variant, and one that declared this type to
1058    /// be read through its fields finds no struct relation to select at all.
1059    Extern(&'a Extern),
1060}

1066/// The language adapter, as the engine sees it.
1067///
1068/// Every method answers a local question about one value, one call or one
1069/// declaration. None of them walks a type, allocates a name, or decides control
1070/// flow: those are the registry's, which is why a second field, a nested struct
1071/// or a third target costs an adapter nothing new.
1072///
1073/// # Where the settings live
1074///
1075/// Here. The registry stores no configuration of its own and knows no
1076/// precedence rule: it does not hold a table of the binding's choices, and it
1077/// cannot say whether one recorded for a parameter outranks one recorded for a
1078/// type. An adapter keeps its `build.rs` storage — the same storage its v1
1079/// route reads — and answers each question below out of it, addressed by
1080/// [`SelectionQuery::position`] for a value and by the [`Declaration`] for an
1081/// output.
1082///
1083/// What the registry does own is *identity*: [`Target::select`] returns a
1084/// [`Selection`] whose `conversion` key stands for the settings the adapter
1085/// just applied, and the registry reuses one conversion for every value whose
1086/// crossing, relation, children and key all match. Hence the one rule an
1087/// adapter owes it, [`Selection`]'s: equal keys are interchangeable
1088/// conversions, and settings that generate differently get different keys.
1089/// A lookup that silently fell back to a default where the binding asked for
1090/// something the adapter cannot do yet would break it in the other direction —
1091/// the answer must be a reported [`Unsupported`], not the default.
1092pub trait Target {
1093    /// This target's name in a report — `"c"`, `"jni"`. Intrinsic to the
1094    /// adapter, so nothing has to carry it alongside the requests.
1095    const NAME: &'static str;
1096
1097    /// What the adapter calls one way of converting a value.
1098    ///
1099    /// The registry never looks inside it: it compares keys to decide which
1100    /// values share a conversion ([`Selection`]), and to notice a type whose
1101    /// conversion needs its own. The obligations that come with minting one
1102    /// are [`Selection`]'s.
1103    ///
1104    /// An adapter whose settings are plain data can use those directly; one
1105    /// holding something incomparable — a naming closure, say, which cannot be
1106    /// compared to another closure — interns it and uses the index.
1107    type ConversionKey: Clone + Eq + std::hash::Hash;
1108    /// The adapter's own rendering data, retained in the plans and read back by
1109    /// [`Target::render_operation`] and by the adapter's foreign writer.
1110    ///
1111    /// `Clone` because one described operation is applied wherever it is
1112    /// needed: the description is registered once per use site, and the
1113    /// alternative is an adapter allocating its own identities for the registry
1114    /// to trust.
1115    type Payload: Clone;
1116
1117    /// Choose the relation this value is read through, and name the conversion
1118    /// that makes it.
1119    ///
1120    /// This is the one call that sees a [`Position`], and so the only place a
1121    /// per-site choice can take effect: it does so by coming back as a
1122    /// different [`Selection::conversion`].
1123    fn select(&self, query: &SelectionQuery<'_>) -> TargetSupport<Selection<Self::ConversionKey>>;
1124
1125    /// Describe what carries this value and how its parts are accessed, for
1126    /// the conversion [`Target::select`] named.
1127    fn represent(
1128        &self,
1129        shape: &ResolvedShape<'_>,
1130        children: &[ChildValue<'_>],
1131        conversion: &Self::ConversionKey,
1132    ) -> TargetSupport<ReprSpec<Self::Payload>>;
1133
1134    /// Describe the wrapper that will export this source function: its
1135    /// interface, and its routes for the failures its conversions can raise.
1136    ///
1137    /// What the binding asked for this export — its symbol above all — the
1138    /// adapter reads from its own storage under [`SiteDescriptor::declaration`].
1139    fn boundary(
1140        &self,
1141        site: &SiteDescriptor<'_>,
1142        values: &ResolvedValues<'_, Self::Payload>,
1143    ) -> TargetSupport<BoundarySpec<Self::Payload>>;
1144
1145    /// Describe one public declaration and what it requires, from what the
1146    /// binding recorded under [`SurfaceRequest::declaration`].
1147    fn surface(
1148        &self,
1149        request: &SurfaceRequest<'_>,
1150        values: &ResolvedValues<'_, Self::Payload>,
1151    ) -> TargetSupport<SurfaceSpec<Self::Payload>>;
1152
1153    /// Render one of this target's operations as a single Rust expression.
1154    ///
1155    /// One expression and nothing around it: no `let`, no `match`, no return.
1156    /// The operands arrive already named by the writer, in the order the
1157    /// operation's specification lists them.
1158    fn render_operation(&self, payload: &Self::Payload, operands: &[syn::Ident]) -> TokenStream;
1159
1160    /// Say, for the report, what this declaration is: the adapter's own
1161    /// declarator word and where the thing lands in the foreign language.
1162    ///
1163    /// Read from the same storage [`Target::boundary`] and [`Target::surface`]
1164    /// read, under the same [`Declaration`], so the report cannot say one
1165    /// thing and the generated code another. Asked of every requested output,
1166    /// including one that was skipped — the report says what a declaration was
1167    /// *for*, not only what became of it.
1168    fn describe(&self, declaration: &Declaration) -> Described;
1169}

1171/// How a report names one declaration on the foreign side — see
1172/// [`Target::describe`].
1173#[derive(Clone, Debug, PartialEq, Eq)]
1174pub struct Described {
1175    /// The declarator that produced it (`opaque_ptr`, `data_class`, `fun`, …)
1176    /// — the adapter's own word, printed back verbatim. Finer than the prefix
1177    /// a [`Declaration`] prints with: `opaque_ptr` and `data_struct` are both
1178    /// a `type`.
1179    pub representation: String,
1180    /// Where it lands in the target language, spelled the way that language
1181    /// spells it: `calculator_t`, `io.zenoh.jni.Session`.
1182    pub placement: String,
1183}
