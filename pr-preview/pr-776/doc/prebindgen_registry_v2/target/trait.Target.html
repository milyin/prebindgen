Expand description

The language adapter, as the engine sees it: a set of writers.

Nothing here decides anything a plan depends on. Which carrier holds a value, which operations move it, what form an exported function takes and which wire types each place may hold are all stated in the Binding before planning starts, and the registry plans from that alone. A writer is called only once the plan is complete, is fed everything its piece of text needs, and cannot refuse: whatever could make a value unsupported was decided when the binding was built.

The associated types are the adapter’s own vocabulary, which the registry compares and hashes but never reads.

const NAME: &'static str

This target’s name in a report — "c", "jni". Intrinsic to the adapter, so nothing has to carry it alongside the requests.

Required Associated Types§

Source

type WireClass: WireClass

The adapter’s few wire types, which acceptance is stated in: C’s I64, Pointer, Aggregate; JNI’s Long, Int, Object.

Source

type CarrierMeta: Clone + Eq + Hash + Debug

What a carrier tells the writers beyond its Rust type: C’s name for it, a JVM descriptor and Kotlin type.

Compared, because two carriers of one Rust type may differ in it — every JVM object is a JObject, and one holding an example.Stamp is a different carrier from one holding an other.Stamp.

Source

type Op: Clone + Eq + Hash + Debug

The target’s own operations: a JVM getter call, a throw. C has none.

Source

type OutputMeta: Clone + Eq + Hash + Debug

What only the target’s foreign writer reads about an output: a Kotlin package and name. C has none.

Required Methods§

Source

fn write_operation( &self, op: &Self::Op, feed: &OperationFeed<'_, Self>, ) -> Written

One of this target’s operations, as a single Rust expression.

One expression and nothing around it: no let, no match, no return. The feed names every operand and says what each holds.

Source

fn write_carrier(&self, feed: &CarrierFeed<'_, Self>) -> Vec<TokenStream>

The Rust items a carrier needs declared, in order — a repr(C) struct or enum mirror, an incomplete type behind a pointer — or none for a type Rust already has, such as i64 or JObject.

The registry puts the condition of the source item the carrier serves on every item returned, so each is one item.
